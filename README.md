# Rotorever

Web3D 遥控直升机物理原型。Three.js 负责显示，独立 TypeScript 模块负责动力学。没有移植 HELI-X 核心代码或机型参数表。外观模型来自用户指定的 RotorflightCN 项目，具体来源记录见下文。

## 运行

需要 Node.js 22.17 或更新版本（测试使用 Node 内置 TypeScript 类型剥离）。

```sh
npm install
npm run dev
```

打开终端显示的本地地址，默认 `http://127.0.0.1:5173/`。

```sh
npm test        # 物理、遥控器、声音、地图缓存与版本提示回归
npm run build  # TypeScript 检查及生产构建
npm run preview
```

仓库包含运行源码、测试、分析脚本和压缩后的场景素材；本地 `analysis/` 分析结果、`backups/` 录像备份、依赖与构建产物不提交。分析脚本需要自行提供参考录像。

构建产物位于 `dist/`，可由静态服务器运行。运行时无需远程字体、图片或云服务。

### GitHub Pages

部署工作流位于 `.github/workflows/pages.yml`：推送 `main` 或手动触发后，安装依赖、运行测试并构建，再发布 `dist/`。仓库的 Settings → Pages → Source 需设为 GitHub Actions。

项目站点路径为 `/rotorever/`。工作流使用 GitHub Pages 提供的路径构建，模型和天空盒也使用同一个资源前缀。本地验证该部署构建：

```sh
npm run build -- --base=/rotorever/
npm run preview -- --base=/rotorever/
```

打开预览地址下的 `/rotorever/`。在线站点使用 HTTPS，遥控器按浏览器的 Gamepad API 权限与交互要求连接；本地页面与在线页面分别保存设置。

## 界面与操作

全屏固定地面机位；黑 / 白 / 蓝界面，仅保留右上角菜单、底部中央双杆和右下角动力遥测。没有顶部栏、侧栏、高度 / 地速覆盖层、暂停、悬停起步或手动复位按钮。主界面没有机型文字；GLB 头罩材质在加载时改为白色。

右上角菜单支持鼠标悬浮、点击和键盘焦点展开：

- **机体设置**：机体参数（起飞重量 / 定速转速 / 电机扭矩）、飞行参数（PID / FF / B 与滤波）、速率设置（斜盘 / 尾舵 Rate、Expo、正负对称集体螺距）。
- **飞场设置**：三张地图可选，默认河畔高清；其他地图手动下载后切换，本地缓存。当前无风。
- **遥控器设置**：AETR 默认映射、行程校准、反向 / 死区、独立电机解锁开关。
- **声音设置**：总音量、五通道混音、主桨朝向强度及爆桨 / 尾桨换向参数，实时生效并保存。
- **使用介绍 / 更新**：首次运行展示简短设置介绍；升级后自动展示一次当前版本更新，关闭后不再重复弹出，可从菜单重新查看。完整历史见 [更新记录](CHANGELOG.md)。

飞机从地面自动起转，逐渐增加总距即可起飞。3D 角速度模式下，方向杆指定机体转速，松杆保留姿态；没有定高或位置保持。滚轮改变视野，飞手位置始终固定。开关由映射的解锁通道控制；未分配时空格可启停电机。默认总距范围 ±12°，可在速率设置中修改。

| 输入 | 功能 |
| --- | --- |
| W / S | 持续增加 / 减少总距 |
| 方向键 | 横滚 / 俯仰；上箭头使机头向前下倾 |
| A / D | 偏航 |
| Space | 未映射解锁通道时启停电机 |
| C | 恢复地面机位的默认视野 |
| 滚轮 | 改变视野角度 |
| 屏幕摇杆 | 左杆：偏航与总距；右杆：横滚与俯仰 |

欢迎介绍和飞场设置打开时暂停飞行，关闭后自动继续；切换地图成功后回到起飞点。机体设置和失焦不暂停，后台运行速率由浏览器决定。遥控器设置打开时强制关闭电机、清零操纵，但物理继续计算，避免校准摇杆触发飞机运动。关闭后恢复输入；已分配的解锁通道重新控制电机。断连会关闭电机并回到起飞点，同一设备重新连接后自动恢复。

相机始终站在地面固定地点 `(-9, 1.8, 0) m`，只转头看飞机；当前照片的眼高按 1.8 m 估算，起飞点距相机 9 m。滚轮通过 20°～65° 视野角调整缩放，C 恢复 42°。

飞行声音已接入实际 RPM、正负螺距负载、抽杆爆桨和尾桨换向。主桨持续声与爆桨共用桨盘朝向增益，桨盘正对镜头最响、侧对最轻；尾桨声源位于实际尾端，自旋时按尾端与摄像机的真实远近循环变化。持续旋转声由程序合成，两种爆发声使用用户录像处理后的采样；完整标定、素材来源与验证入口见 [声音系统](docs/sound-system.md)。首次点击或按键启用音频，后台和暂停时自动淡出。

水平朝向逐帧紧跟，垂直仰角采用 100 ms 时间常数的一阶跟踪，使高频总距抽拉时的真实上下运动保留在画面内。按帧间时间解析积分，不对机体位置或输入加滤波；垂直偏移限制在中心上下各 17.5% 画面高度，避免急爬升时丢失飞机。炸机复位立即重新对准，镜头没有弹簧回摆或人为震动。

`node --experimental-strip-types scripts/collective-frequency-benchmark.ts` 验算 2 / 5 / 6 / 8 Hz 总距响应，区分实际桨距、加速度、位移与镜头呈现。固定回归工况 5 kg / 2400 RPM，6 Hz、悬停总距上下各 4°、60 Hz 输入采样时，桨距基频幅度保留 99.96%，垂直位移约 3.77 cm 峰峰值；原相机将其完全抵消为画面中心不动，新相机在 9 m、42°、720p 下呈现约 3.8 px 上下运动（各 8° 时约 7.6 px）。这是本模型的频率验算，尚非 HELI-X 同输入高频录制对照。`tests/collective-camera-harness.html` 可切换两种镜头观看同一物理轨迹；本次不修改升力、质量、阻尼或用户已保存的参数。

### 地图下载与本地缓存

每次启动仅加载列表第一张「河畔草地飞场 · 高清」，先 256px 预览、后 2048px 标准面。飞场设置采用「缩略图 + 文字」网格卡片，按窗口宽度显示三列、两列或单列；打开时才加载独立的 640×400 WebP 缩略图，并读取本地缓存状态。另两张地图的完整纹理必须点击「下载地图」才请求资源；下载成功后点击「进入飞场」，重复切换只读本地缓存。缩略图不计入地图下载状态，也不会在启动时预取。

`src/field-assets.ts` 使用 CacheStorage（HTTPS 或 localhost），按文件 SHA-256 区分版本，下载时验证字节数与哈希。12 张图片全部保存后才标记「已下载」。失败和空间不足会提示重试，部分下载可续传；缓存被清理或素材更新后，非默认地图仍需手动下载，不会自动补流量。默认地图在浏览器无法写缓存时仍可在线显示。缓存属于当前浏览器和站点，可被浏览器回收；不等于整个网站可离线启动。

切换同步更换背景、反射、光照和机位，释放旧背景纹理与环境反射目标。原始素材和测试页面不会进入生产下载。`tests/field-download-harness.html` 提供独立测试缓存、逐地图请求计数和地图断网开关；可检查初次只请求默认地图、下载失败重试、缓存跨刷新复用和离线切换。

### 自有 X5 草地飞场（保留）

此前的实拍地图来自用户提供的 `IMG_20260312_105849_00_004.dng`，Insta360 X5 于 2026-03-12 拍摄，11904 × 5952，约 142 MB。原始文件是双鱼眼 CFA RAW，不能直接当作 2:1 全景贴图。来源、处理标定、资源哈希与统一场地配置记录在 `public/environments/x5-grassland/manifest.json`；可在飞场设置下载并切换。原片留在本地并被 Git 忽略。

- **离线处理**：应用 DNG 内 8 张镜头亮度增益图、相机白平衡与高光处理，按完整 11904 × 5952 分辨率解码，再用照片的 MEI 镜头参数重投影。333 个重叠区域特征点拟合双镜头焦距尺度及相对姿态，中位角度残差约 0.086°；189 条建筑线段拟合竖直方向，校正约 9.4° 的持机倾斜。重叠处窄带羽化，直接采样成立方体六面，浏览器无需解码 RAW、拼接或进行全景投影转换。
- **加载**：六面 256 px WebP 预览 50,228 字节，随后换为六面 2048 px WebP（质量 92）3,348,762 字节，合计约 **3.40 MB**，比原始 DNG 小约 97.6%。采用完整解码和较高画质，保留放大后的草地、建筑细节。主背景纹理采用双线性采样，不生成 mipmap，RGBA8 显存约 **96 MiB**，预览约 1.5 MiB；环境反射与阴影另占显存。WebP 缩小下载体积，本身不是 GPU 压缩格式。
- **朝向 / 空间**：大片开阔草地烘焙在世界 `+X` 方向，初始镜头和起飞点沿此方向；拍摄者与手持机体位于侧后方。眼高 1.8 m、起飞距离 9 m 是体验尺度估算，单张照片不能提供真实测距。物理与深度遮挡共用 `y=0` 平面；相机只旋转，不平移，避免全景产生不成立的视差。
- **碰撞 / 遮挡**：保留物理脚架接触、桨盘触地及炸机复位；可见场地下有独立深度遮挡面，飞机不能透过草地显示。碰撞不依赖纹理是否加载完。照片里的树木、房屋是背景，没有虚构它们的距离或添加碰撞体。
- **太阳 / 阴影**：从原片太阳亮斑反投影到校正后的坐标，估算太阳在初始镜头右后方，相对草地方位约 **155.3°**、仰角约 **55.1°**；这不是地理方位角。入射光方向约 `(0.5197, -0.8201, -0.2394)`，阴影向前左方延伸。透明 ShadowMaterial 地面使用 0.5 阴影强度；1024² 阴影图的 3.2 m 窗口跟随机体，深度范围随高度更新。机体静态零件合并为一个阴影批次，低转速桨叶单独投影，高速半透明桨盘不投实心圆形阴影。
- **光照 / 降级**：背景以 sRGB 显示，机体使用太阳光、草地 / 天空半球光及从 256 px 预览生成的低分辨率环境反射。预览失败仍尝试标准纹理；标准失败保留预览；两者失败保留底色并提示，飞行动力学仍能运行。
- **照片边界**：保留原片内容。近处人物、手臂、自拍杆阴影和桨叶会在侧后方 / 正下方出现，双镜头基线导致这些近物仍有局部拼接视差；草地默认视角与远景建筑已对齐。单张全景不支持走动视差、真实起伏地形或建筑遮挡。

`tests/field-harness.html` 可检查地面、悬停、倾斜、地下遮挡、太阳朝向和全景接缝；加 `?fail=preview`、`?fail=standard` 或 `?fail=all` 可验证加载降级。`tests/field.test.ts` 检查阴影与地面交点、碰撞、出生方向、太阳仰角、资源完整性、部署前缀和素材预算。

### Rates 与响应

默认横滚 / 俯仰 **350°/s**、尾舵 **650°/s**、常规三次 **Expo 40%**。在机体设置的“速率设置”中修改并保存在本机浏览器。采用 `y = (1-e)x + e*x³`：40% Expo 时半杆对应 35% 速率，满杆仍是 100%。这是用户选定的常规 Expo，不声称等于 RF Actual Rates 或其他指定 Rate 类型。Expo 只应用于横滚、俯仰、偏航，不作用于总距；若发射机自己也设置了 Expo，两层曲线会叠加。

方向键与 A / D 现在可以打满杆，不再暗中打七折。遥控器校准、死区与反向完成后输出直接进入 Rates，没有新增输入平滑层。底部中央双杆显示实时操纵量。

现在采用扭矩域 PID + 稳态 FF + 加速 Boost，驱动有限速的舵机、桨盘和尾桨。桨毂周期操纵项按 RPM² 衰减，在负总距下保留操纵方向。角速度仍从力矩和转动惯量积分。

### 飞控调参

2026-10-15 根据用户 Chrome 中已应用的配置更新机体默认值：**2.8 kg / 2150 RPM / 电机扭矩 50% / 螺距 ±12° / 斜盘 350°/s / 尾舵 650°/s / Expo 40%**。总距升力增益 / 旋翼轴向阻尼 / 机体空气阻力为 **70 / 120 / 100%**。横滚和俯仰 P / I / D / FF / B 为 **50 / 30 / 0 / 150 / 40**，尾舵为 **85 / 30 / 0.35 / 0 / 40**；D / B / I Relax 滤波为 **60 / 25 / 12 Hz**，自旋补偿开启、强度 100%。首次打开、无有效保存配置以及面板的飞控/气动“恢复默认”均使用这套配置；已有有效机体配置继续优先加载，旧配置缺少气动字段时仍补齐原有 100% 基准。物理参考质量、惯量与历史验算工况保持独立；`scripts/benchmark-aircraft.ts` 固定历史 5 kg / 2400 RPM 回归配置，运行时由 `applyAircraft` 应用当前机体配置。

机体设置的“飞行参数”可独立编辑横滚、俯仰、尾舵的 **P / I / D / FF / B**、滤波频率以及**自旋优化开关 / 补偿比例**。点击“应用设置”后生效，页面保持打开；关闭放弃尚未应用的修改。“恢复飞控默认”填入全部飞控默认值；“恢复自旋默认”只恢复自旋开关与比例，保留当前 PID 和滤波编辑值，均需应用。

自旋优化参考 Rotorflight 的 Error Rotation：RF 2.2 的 [`error_rotation` 默认开启](https://github.com/rotorflight/rotorflight-firmware/blob/release/4.5.1/src/main/pg/pid.c#L57)，RF 2.3 [在每次 PID 计算前直接旋转误差](https://github.com/rotorflight/rotorflight-firmware/blob/release/4.6.0/src/main/flight/pid.c#L710)。本模拟器默认**开启 / 100%**，每个内部控制步根据实际机体偏航角速度，把横滚、俯仰累积角度误差逆向旋转到新的机体坐标，然后再累积误差、应用各轴惯量与 I 增益。采用 X 横滚、Y 偏航、Z 俯仰的坐标约定；尾舵积分不参与旋转，原有积分限幅、防饱和与 I Relax 保留。

**补偿比例 0～150%，步进 1%** 是模拟器提供的微调扩展，RF 原参数没有这个比例项。100% 对应 RF 的一倍实测自旋角度；低于 100% 少补偿，高于 100% 过补偿；关闭或 0% 恢复原有逐轴积分。建议从开启 / 100% 开始，每次调整 5% 对比左右自旋与组合动作。它不改变摇杆的机体坐标语义，也不提供位置保持或自动回正。RF 的 PID 数值使用不同输出尺度，当前 P / I / D / FF / B 和滤波初值继续保留已验证的模拟器配置。

机体配置保存在 `heli-lab.aircraft.v1`；首次迁移会保留已有 `heli-lab.fbl.v1` / `heli-lab.rates.v1` 设置，遥控器按设备保存的映射与校准也保留。旧机体与旧独立 FBL 配置仅补齐缺少的自旋字段，不覆盖已有 PID、滤波、速率或机体设置；显式关闭和自定义补偿比例可保存并恢复。应用时清空飞控积分和滤波历史；炸机后保留机体配置。重量可调 1～8 kg，定速 1200～3000 RPM，集体螺距 ±5°～±18°。重量同时改变重力、平移惯性，并按基准质量比例调整三轴转动惯量，假设增减质量仍遵循原有分布。

“机体参数”中的 **电机扭矩** 滑杆为相对动力强度，范围 10～100%，不是 N·m 实测值。50% 保留原有动力；10～99% 按强度同步调整扭矩 / 功率上限、定速器增益与扭矩响应速度。**100% 显示“最大 · 理想定速”**，不受有限电机扭矩 / 功率限制，启动完成后保持设定 RPM，满正负总距与尾桨负载均不引起掉转。理想模式仍计算维持转速所需的主旋翼、尾桨及惯性扭矩，用于反扭矩和 HUD；允许理想驱动吸收回馈功率。启动、修改定速转速以及飞行中切入最大档均保留转速斜坡，关闭电机后恢复惯性减速。当前项目默认 50%，缺少此字段的旧配置会补齐该默认值。

推荐三轴初值均为 **P 85、I 30、D 0.35、FF 100%、B 40%**；D / B / I Relax 截止频率为 **60 / 25 / 12 Hz**。三轴独立编辑；不同惯量和力矩上限使实际响应不同。控制项含义如下：

| 参数 | 本模拟器中的定义 | 单位 |
| --- | --- | --- |
| P | 角速度误差 × 转动惯量 × P | P 为 s⁻¹ |
| I | 累积角速度误差 × 转动惯量 × I | I 为 s⁻² |
| D | 测得角加速度的一阶低通 × 转动惯量 × −D；对测量求导，避免目标阶跃直接产生 D 冲击 | 无量纲 |
| FF | 目标角速度所需的模型阻尼力矩 × FF / 100 | %；100% 对应当前模型阻尼 |
| B | 目标角速度变化率的一阶低通 × 转动惯量 × B / 100 | %；加速前馈 |

五项输出相加并加上刚体耦合补偿，再进入执行器限幅 / 限速。尾轴另有电机反扭矩补偿。积分误差上限为 ±0.4 rad；饱和时停止继续积累，允许反向卸载；I Relax 在快速打杆时抑制新的积分积累。地面及低转速时清空积分。总距直接进入舵机，与这组三轴角速度 PID 分开。

参考 [Rotorflight Profiles](https://rotorflight.org/docs/configurator/tabs/profiles) 中 P/I/D、前馈、Boost、I Relax 的分工。RF 的 [前馈调校说明](https://rotorflight.org/docs/Tuning/Tune-Feedforward) 区分持续速率 FF 与改善瞬态响应的 Boost。这里为独立的降阶物理控制器，**增益尺度不等于 Rotorflight，不能直接照搬真机数值**，也未实现 RF 的完整控制算法。

2026-10-09 参数调整：P 32 → 85，I 16 → 30；增加 D / B 和 I Relax。桨盘 / 尾桨时间常数 12 → 8 ms，等效变距速度 700 → 900°/s，桨毂等效刚度 100 → 160 N·m/rad（2100 RPM），尾桨最大侧推力 14 → 20 N。质量和机体转动惯量保留。这些仍是 **未实测标定的 550 级试验参数**；力矩上限的调整用来改善满杆时执行器持续饱和造成的慢响应，不能据此声称达到真机保真度。

### 遥控器 / 手柄设置

1. 遥控器切到 USB HID / 游戏控制器模式，连接电脑，点击页面并拨动摇杆。浏览器一旦暴露设备，单台新遥控器即自动启用，不需要打开设置或保存。
2. 新配置默认 **AETR：CH1 副翼、CH2 升降、CH3 总距、CH4 方向；CH6 解锁电机**。高位启动、低位关闭。设备没有 CH6 时默认空格启停，也可选独立轴或 HID 按钮。已有有效配置保留原映射与校准。
3. 需要调整时打开“遥控器设置”，修改通道与反向，再点击固定在底部的“保存设置”。右上角关闭按钮也固定，只有中间内容滚动。选择输入设备即连接，不以保存为启用前提。
4. “校准与更多设置”包含中位 / 行程校准、死区和原始通道。所有摇杆回到中间，记录中位，走满两端，再完成校准并保存。取消采集不覆盖已有数据；解锁通道不参加中位 / 行程校准。

自动连接结合设备识别与本地使用记录：优先恢复当前连接设备中最近用过的一台；上次用过的设备不在，也不会挡住其他遥控器。首次连接通过 EdgeTX / OpenTX 固件名称、USB 标识 `1209:4f54` 和非标准映射的四轴以上 HID 布局识别候选设备，不依赖厂家名单。普通标准游戏手柄首次需手动选择，之后也会记住；保存按钮只用于保存通道与校准修改。

使用记录按设备标识与通道布局保存，浏览器设备编号变化不影响匹配。没有有效保存配置时使用默认映射，浏览器不允许存储也可在当前会话飞行。多台同优先级、或同型号且布局相同的设备需手动选择；Gamepad API 不提供设备序列号，也不能保证未知 HID 的通道顺序一定是 AETR。已启用设备不会被后来接入的设备抢占，断连时关闭电机，其他已连接设备不会立即接管。

选择“键盘 / 触控”只停用当前连接的设备；重新插入设备或刷新页面会恢复自动连接。旧版本持久保存的键盘模式不再阻挡自动识别。浏览器仍可能要求先点击页面、拨动摇杆或按键，才能向网页暴露设备。

Gamepad API 每帧轮询，不额外增加输入平滑层。断连或输入无效时关闭电机，原设备恢复后自动重新连接；不会接管同索引的其他设备。解锁输出采用 ±0.05 滞环，开关不能与飞行操纵共用轴。相同 ID / 轴数 / 按钮数 / mapping 的设备共享浏览器配置。

自动测试覆盖首次接入、刷新、拔插、多设备优先级、旧版键盘模式迁移、CH6、已有校准与存储失败。`tests/gamepad-first-use-harness.html` 用空白配置和模拟 HID 运行实际飞行页面，`tests/gamepad-auto-harness.html` 使用独立会话存储验证自动连接与刷新，`tests/gamepad-harness.html` 验证校准界面；这些页面均不访问真实遥控器配置。远程页面需 HTTPS，真实设备兼容性仍需飞友实测。

## 当前解算

所有动力学单位为 SI；角度在核心内为弧度。机体系及初始世界系均为 **X 前、Y 上、Z 右**。机体角速度 x 为右横滚，y 为向左偏航，z 为抬头。显示层直接采用同一坐标系。

外部输入每 4 ms 更新；每步再细分为两个 2 ms 动力学子步，执行：

1. 将相对风速变换到机体系，计算角速度目标；姿态辅助是角速度控制器的外环。
2. 扭矩域 PID、稳态 FF、加速 Boost 与刚体耦合补偿生成有限幅、有限速度的周期操纵，经过一阶桨盘响应；结合饱和保护和 I Relax 限制积分累积。
3. 飞行转速下采用从用户录像辨识的三个正值力导数：有效总距、轴向气流和动态入流反馈；按空气密度、实度、半径及转速缩放。质量只进入 F=ma，不被隐藏地用于保持固定加速度。超过拟合螺距范围后连续饱和；极低转速平滑过渡到 12×8 叶素计算，保留被动气流载荷。轴向/诱导功率与桨叶剖面阻力决定气动扭矩，支持负载回馈和正负总距。
4. 基于正则化动量关系求均匀诱导速度目标，以一阶状态表示入流建立过程。
5. 定速器结合扭矩/功率限制、旋翼气动扭矩、尾桨负载及旋翼惯量更新转速。
6. 简化尾桨侧推力与偏航控制，包括主旋翼驱动反扭矩补偿、执行器延迟和转速相关的推力上限。
7. 汇总机体力、作用点力矩、简化桨毂力矩、空气阻力及四个起落架接触力。
8. 积分 `m dv/dt = ΣF`、`I dω/dt = M − ω × Iω`，有地面接触时再求解有限静/滑动摩擦冲量。平移采用半隐式 Euler，四元数使用中点角速度的指数映射并归一化。

旋翼转速由 `J dΩ/dt = Qmotor − Qaero − Qtail − Qfriction` 更新，而不是直接赋目标转速。熄火后旋翼仍保留惯量。

### 大集体与大循环的负载（2026-10-15，本地试验）

`src/physics/rotor-maneuver.ts` 为原有辨识模型补充高迎角负载。集体螺距（总距）是整圈共同的 `θ₀`，循环变距是 `θ₁c cosψ + θ₁s sinψ`，不能把循环杆量直接加到一个总距标量上。低速机动采用一个代表半径 `0.75R`、八个等距方位和一个分离状态，计算量固定，不求解流体网格：

```text
α(ψ) = θ₀ + θ₁ cosψ − atan2(V轴向 + v诱导, Ω × 0.75R)
x(ψ) = clamp((|α(ψ)| − α失速) / Δα, 0, 1)
S目标 = mean[x²(3 − 2x)]
dS/dt = (S目标 − S) / τ                 建立 8 ms，恢复 60 ms
ΔCd = 0.018 × (a θ₁)² / 2 + 0.22 S
ΔQ剖面 = B ρ c (R⁴ − r根⁴) Ω² / 8 × ΔCd
T = T原模型 × (1 − 0.75 S)
Q主桨 = Q原模型 + (T − T原模型)(V轴向 + v诱导)/Ω
        + ΔQ剖面 + max(0, M横滚 ω横滚 + M俯仰 ω俯仰)/Ω
```

`S` 是有效分离程度，**不是实际桨盘面积的测量值**。失速起点暂取 13°，过渡宽度 7°；桨毂操纵效率也随 `1 − 0.25S` 减弱。主桨新增负载进入已有电机扭矩/功率限制和旋翼惯量方程，尾桨功耗仍单独加入，不直接按杆量强制降低 RPM。电机设置 100% 仍为理想定速：它提供所需扭矩，转速不掉，但桨叶效率损失仍存在。低于约 382 RPM 不叠加新修正，随后随转速逐渐接入；公式中的除数均做低转速保护。

根据后续试飞反馈，失速推力损失系数从 `0.45` 提高到 `0.75`，失速起点、阻力、循环操纵效率及建立/恢复时间保持原值。2400 RPM、零机体速度、固定诱导速度 4 m/s、12° 集体叠加 12° 等效循环的稳态对照中，推力损失从 **15.6% 增至 26.0%**，推力约 **344 → 301 N**。低于失速起点的工况不受该系数影响；这次是高迎角手感调参，不是重新进行了实机标定。

现有 FBL 执行器控制的是等效桨盘倾角，尚无独立的机械循环桨距状态。因此 `θ₁` 由执行器合成角与 `4 × |ω横滚俯仰| / Ω` 近似重建，上限 12°，不是把盘面倾角声称为真实桨距；暂不区分循环相位与前飞方位效应。所有新增系数均为待标定的模型参数，不是实测桨叶极线。旋转做功按实际施加的主桨横滚/俯仰力矩计入，负做功按耗散处理，不假设未建模的能量回收。

同样的脚本输入：5 kg、2400 RPM、±12°、350°/s、正常气动增益、电机 90%，从悬停开始，0.2–1.2 s 持续给杆，之后卸载 1.8 s：

| 工况 | 最低 RPM，原模型 → 新模型 | 主桨峰值气动负载，原模型 → 新模型 |
| --- | --- | --- |
| 3° 集体＋满升降 | 2398 → 2392 | 3.37 → 5.60 N·m |
| 12° 集体，循环居中 | 2261 → 2261 | 16.22 → 16.22 N·m |
| 12° 集体＋满升降 | 2225 → 2155 | 16.20 → 20.08 N·m |
| 12° 集体＋满横滚 | 2223 → 2191 | 16.19 → 16.67 N·m |

新增测试覆盖局部迎角/正负流向对称性、非线性叠加、分离恢复、旋转做功、有限电机掉转与恢复、理想定速、步长减半。原有 5–6 Hz 集体、FBL 起停、尾桨锁定及传动功率平衡回归仍通过。长时间 ±12° 集体往复的最低转速因新增分离阻力从约 2100 降至 1970 RPM，尾桨测试允许这部分真实负载变化，偏航误差门槛保持不变。

这次实现**不代表已标定极限动作的真实掉转幅度**。没有加入桨叶折叠、摆振/弹性方程、空间尾涡吸入、BVI 声音或随机推力惩罚。已有均匀动态入流保留，但它不能替代旋翼穿越自身尾迹的模型；失速分离状态也不能替代包含涡脱落/迟滞的完整动态失速模型。NASA 对[动态失速、桨涡相互作用与柔性桨叶耦合](https://nas.nasa.gov/pubs/stories/2019/feature_rotorcraft_bvi_chaderjian.html)的说明用于建模方向参考，不作为这些数值系数的来源。


接触使用法向弹簧阻尼和受 `|J切向| ≤ μJ法向` 限制的摩擦冲量。四个接触点在静摩擦范围内可以保持不滑动，超限仍会滑动；离地后没有接触冲量。过重接地、倾覆接地或旋翼触地后，界面立即把飞机重置到地面起飞点、总距归零并重新起转，不弹窗、不要求确认；若映射了解锁通道，则优先遵从开关状态，锁定时电机不会自行启动。保留机体配置和遥控器校准。复位时包含四个起落架承重所需的毫米级静态压缩，尚未实现机体任意形状碰撞。

### 地面启动锁尾修复（2026-10-15，本地试验）

主尾桨一直通过 `80/19` 齿比联动，尾桨可用推力随其转速平方变化。启动甩尾的原因是：低转速下尾桨推力尚小，主轴加速反扭矩已经很大；原来的地面摩擦只随滑动速度增长，没有静摩擦，必须先发生滑动才能抵抗扭矩。

`ground.ts` 现在用四点切向顺序冲量求解接触，最多 12 次迭代，仅在接地时执行。每个冲量受同一摩擦系数 `0.65` 和实际法向载荷限制，同时改变线动量和角动量；不直接固定机头方向或清零角速度。方法背景见 [Box2D 的接触/摩擦说明](https://box2d.org/documentation/md_simulation.html)。法向支撑仍使用原有弹簧阻尼，不引入新的运行依赖。

启动转速斜坡在 0–900 RPM 范围从原最大加速度的 8% 平滑增加到 100%，900 RPM 以上沿用原有最大斜率；同时在定速器前馈里补上目标转速上升需要的 `J × dΩ目标/dt` 扭矩，避免 PI 在启动阶段积累过多误差。冷启动和在飞行转速附近的快速恢复因此有不同响应；这是独立的简化实现，参考了 [Rotorflight 区分启动、起转与飞行恢复阶段的设计](https://doc.rotorflight.org/contributing/tech/governor/)，不是移植其控制器或参数。

5 kg / 2400 RPM / 电机 90% / 零集体，连续地面启动测试：最大机头偏转 **14.02° → 0.0011°**，最大偏航速度 **35.40 → 0.062°/s**，启动峰值转速 **2669 → 2422 RPM**；到达 95% 转速由约 1.63 s 改为 **4.03 s**。电机 100% 的地面偏转也降到约 0.0011°，仍保留理想定速。机体质量 3.2/5/8 kg、1800/2400/3000 RPM、电机 50/90/100% 的组合，页面初次加载、静置后启动、停机重启、起飞及步长减半均纳入回归。

空中没有静摩擦：零转速、无地面支撑时仍会因主轴加速反扭矩偏航；尾桨推力也没有绕过低转速上限。启动测试逐步核对主桨、尾桨和旋翼加速的轴扭矩平衡；摩擦测试核对有限冲量、动量变化和能量耗散。复算：`node --experimental-strip-types scripts/startup-benchmark.ts`。

物理层 `hover()` 仍用于回归测试和开发回放，联立主旋翼载荷、尾桨反扭矩、机体侧倾、发动机负载进行配平。生产界面从地面起飞，没有悬停起步入口。

输入调度固定 250 Hz，内部动力学 500 Hz，画面插值显示。单次画面停顿超过 100 ms 时丢弃多余墙钟时间，避免用大步长破坏积分；因此严重卡顿时仿真会比真实时间慢，积分分辨率不是浏览器实时调度保证。

运行 `node --experimental-strip-types scripts/response-benchmark.ts` 可复查响应。条件：2100 RPM、总距 +0.27、350/620°/s、40% Expo、250 Hz；序列为零 → 正杆 → 等量反杆 → 零，每段 600 ms。旧版与新版均使用相同序列和测量方式。

| 指标 | 横滚 旧 → 新 | 俯仰 旧 → 新 | 尾舵 旧 → 新 |
| --- | --- | --- | --- |
| 25% 杆量起动至 90% | 56 → 20 ms | 56 → 24 ms | 56 → 24 ms |
| 满杆起动至 90% | 56 → 24 ms | 80 → 52 ms | 124 → 80 ms |
| 满杆换向至阶跃完成 90% | 60 → 32 ms | 128 → 80 ms | 148 → 108 ms |

“稳定”指余下观察期间持续处于 ±max(1°/s, 指令速率 × 2%) 以内，避免只测首次穿越阈值而漏掉回弹。25% 实际杆量经 Expo 后为 15.625% 角速度目标。新回归覆盖 1800/2100/2600 RPM、正反小杆和正/零/负总距的换向与刹停，以及三轴增益的独立实际效果、配置校验 / 恢复。这里只衡量模型动态，不是硬件端到端延迟，也不能代替真实遥控器试飞反馈。

当前开发目标（2026-10-10）：以 **HELI-X 在 550 / 700 级直升机上共同呈现的操纵响应**为参照，达到用户所描述的“像调教良好的现代 Rotorflight”的体验。不要求用户采集真机日志、加速度计或 GPS 数据，不以选定某一机型或真机物理精度认证作为推进条件。

### 2026-10-10：第一轮 HELI-X 录像与总距验算

完整结果见 [分析报告](analysis/helix-response-report.html)，可通过开发服务器 `/analysis/helix-response-report.html` 打开。独立曲线在 [PNG](analysis/collective-response.png) / [SVG](analysis/collective-response.svg)，全部聚合统计和实验采样保存在 `analysis/`，源文件哈希在 `analysis/analysis-manifest.json`。此次只新增分析工具和测试，没有修改生产物理参数或用户配置。

- 59 份本机 `.fly`、155,160 帧全部解析通过；45 份扩展格式、14 份旧格式，其中 4 份为固定翼。独立读取器只解析记录，不运行 HELI-X 代码。序列化顺序与运动学交叉验证确认了姿态矩阵、世界位置、世界速度、四路记录操纵量和微秒时间轴。其他字段保留结构，不擅自当作 RPM、扭矩或角速度。
- 姿态矩阵最大正交误差约 `3.28e-7`；有平移运动的记录中，位置变化与速度积分的整体比例在 `0.9998–1.0069`。筛掉大时间间隔、运动学残差过大、低高度和大角度区间后，选择 6 份直升机演示做行为拟合。
- 这些录制元数据主要来自 2013–2021 年，约 30 ms 一帧，没有完整录制时配置，也没有匹配的 550 录像。描述性拟合不能证明当前 HELI-X 的几毫秒延迟、原始 FBL 系数，或 550/700 通用手感已标定。三轴输入/角速度最佳匹配落在 0 ms 的 30 ms 网格上，不代表零延迟。
- 当前 Web 在明确指定的 3.8 kg / 2400 RPM / ±13° / 理想定速实验中，悬停→满总距的桨距到位约 12 ms；100 ms 的垂直速度约 5.06 m/s。把舵机速度提高 100 倍后为 5.21 m/s，把入流常数从 90 ms 改为 5 ms 后反而为 4.49 m/s。缩短常数不能自动改善加速感。
- 同工况下，100→500 ms 垂直加速度约 40.92→14.21 m/s²，此时速度升至 14.84 m/s。固定零空速的对照把入流动态与爬升气流影响分开；不能把整个推力下降解释成输入延迟或直接认定为错误。
- 从悬停以 +50% 总距上升 0.5 s 后，反打 −50% 总距约 92 ms 使垂直速度过零，零总距约 380 ms，回悬停总距在 1.5 s 内未过零。这三种指令不能用同一个“刹停时间”评价。
- 录像的低记录速度片段提示应优先标定有效总距力度与轴向速度敏感度。回归仍混有飞手闭环、未知风速、转速及历史模型差异，不能把统计系数直接移植到 Web。强下降/自转区的均匀入流局限仍未解决。
